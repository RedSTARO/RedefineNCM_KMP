# Android 折叠屏自适应验收

目标为 Google Play [Tier 3（Adaptive ready）](https://developer.android.com/docs/quality-guidelines/adaptive-app-quality/tier-3)。验收的重点是窗口变化时仍能完成原来的操作，不以双栏数量作为达标标准。这是本地 QA，不是 Google Play 全项认证。商店截图是[另外的提交要求](https://developer.android.com/blog/posts/google-play-adaptive-quality-standards)，本次不操作 Play Console。

## 实现约束

- Launcher Activity 可自由旋转和调整大小，没有宽高比限制。窗口大小、屏幕布局、密度和外接键盘配置变化由现有 Activity/Compose 响应，不重启播放器或重建路由。系统语言、字体、主题等其余变化仍可重建 Activity，普通 UI 状态走 Android SavedState 和按路由隔离的 Compose 状态；账号草稿、QR/SMS 会话只保存在内存中，凭据/服务器地址只有用户显式提交才写入设置。
- 窗口排布以实际可用尺寸为准，不判断机型。普通外屏保留悬浮导航；宽度不足 320 dp 或高度不足 480 dp 时，用一条底栏同时容纳三个入口与播放器入口，不再叠加迷你播放器。宽度至少 600 dp 且高度够用才使用侧栏。导航模式在软键盘扣除空间之前决定，窄窗底栏在编辑时隐藏。无实体遮挡的折痕不拆分浏览页；有遮挡时用最大可用矩形，不跨铰链。
- 播放页的背景仍铺满，交互内容避开系统栏、手势区和遮挡。近方形窗口不因为扣除系统栏后略宽于高就切成双栏。只有宽高比和空间均合适，或分隔折痕两侧确实放得下页面内容时，封面/歌词与控件才分开；薄窄半屏以及单行、加载、错误歌词进入一个安全区域。上一首、播放和下一首优先整组换小尺寸，不让最后一键单独换行。Android 竖屏歌词的 36 dp 上限继续按整个窗口判断。
- ExoPlayer、队列、MediaSession 和下载管理不依赖 Activity 获焦。听歌识曲是例外：失去 top-resumed 所有权时中止采样并归还被它暂停的播放，焦点回来后由用户重试，不擅自重启录音。触摸屏和麦克风不作为安装硬件门槛。

## 2026-11-23 逐轮独立 ADB 复验

子代理每轮只改一个范围；主代理独立重建、安装 `.debug` 候选包，跑完该轮的窗口矩阵再进入下一轮。使用专用 Pixel 9 Pro Fold AVD、Android 16 / API 36、390 dpi。其他模拟器和真机上的应用未被这轮测试接管。

- **每轮窗口矩阵：** 小屏 443×994 dp（CLOSED + 外屏尺寸）、展开竖屏 852×883 dp、展开横屏 883×852 dp、90° 书本与桌面半折、与系统时钟实际分屏（拖短约 852×306–314 dp，旋转到约 296×852 dp）。可见场景均检查 Activity/进程、窗口边界和 `areBoundsLetterboxed=false`。
- **模拟边界：** 当前 AOSP 镜像报告真实的虚拟铰链角度和半开状态，但不自动切换到外屏尺寸，且旧版 Pixel Fold 系统 overlay 的状态映射与本 profile 不同。仅在专用 AVD 覆盖外屏尺寸并注入 Window Extensions 的折痕矩形。应用走原生 AndroidX WindowManager 回调，没有测试专用生产分支；用尺寸不变时书本/桌面布局的变化确认回调进入应用。另以 1099×720 dp 验证足够宽的横屏，并合成不透明铰链测试遮挡。这不是实体铰链或亮屏跨面板验收，也不代替 Google Play 的官方 1:1 / 4:3 配置。

| 轮次 | 独立验收结果 |
|---|---|
| 1 · 导航与浏览（`735a0bc`） | 小屏保留悬浮导航和迷你播放器；展开横竖与不遮挡的半折保留连续浏览。合成不透明铰链下，导航与播放器都不进入遮挡区。真实分屏里三个导航入口和播放器在同一条底栏，逐个可操作；编辑时短窗底栏隐藏，宽窗仍保留侧栏。 |
| 2 · 播放与歌词（`ea6cf9b`） | 小屏、内屏横竖、半折和窄/短分屏都能打开歌词、操作整排传输控件。较宽的横屏按空间分栏；书本半折中正常歌词与控制分别位于两侧，单行/错误状态和较浅桌面半折不强拆。打开队列后切换书本半折仍留在队列；真实分屏中时钟获焦时，离线测试 WAV 仍是 `PLAYING`，进度 `45,694 → 48,727 ms`。歌词视觉使用独立的合成双语数据，不把它当作可播放音源。 |
| 3 · 状态接续（`abe3d67`） | 在外屏尺寸、内屏横竖、两种半折与真实分屏中验证搜索草稿和键盘行为。跨形态后输入字符准确替换了原先选择的后缀；手动关闭键盘后不会因折展重新弹出。100 行合成结果回到展开竖屏时仍为第 006 行，边界同为 `[507,407][828,455]`。应用语言变更实际销毁并重建 Activity，修复了原来跳回首次登录的问题；搜索草稿与焦点保留，原本打开的 IME 恢复，手动关闭的 IME 保持隐藏，点击字段或从首页发起搜索可以重新唤起。 |

## 2026-11-24 折展动效复验

按上面的窗口矩阵逐轮验收，沿用同一台专用 Pixel 9 Pro Fold AVD 和合成数据。在静止画面上用 `adb shell screenrecord` 录折展前后，逐帧对照正常动画比例与系统「移除动画」（Animator duration scale `0×`）。录帧用来区分应用动效和系统窗口变化，不作为真机帧率基准。

- **播放与歌词（`4630686`）：** 新版先按当下可用窗口和折痕摆放内容，再让目标内容短暂淡入；没有旧控件跨过铰链，背景不随重排淡入。展开竖屏切到书本半折时，逐帧看到播放键在新位置由浅到实；`0×` 时第一帧即是最终对比度。桌面半折也看到同样的收稳，歌词页返回键同样遵守 `0×`。布局不变、首次进入、仅键盘变化或加载歌词时不启动新的折展动效。队列在折展后仍打开，分屏让系统时钟获焦时离线音频仍为 `PLAYING`，进度 `42,737 → 48,820 ms`。
- **导航（`20d4cc1`）：** 仅目标侧栏、悬浮工具栏、紧凑底栏和对应的迷你播放器轻淡入，不动页面背景或编辑器。用同分辨率的不透明横向铰链触发侧栏→底栏：旧版录屏有一帧同时显示旧迷你播放器与新底栏；新版首个目标帧仅显示底栏，按钮从浅到实且能进入播放器。`0×` 直接呈现；不遮挡的书本半折保留侧栏且无淡入。外屏尺寸、内屏横竖、两种半折、真实分屏及旋转后均复测了导航。搜索选区能正确替换，返回展开竖屏时第 006 条结果及其可见偏移不变。

真机亮屏跨内外屏、不同 OEM 的铰链/系统过渡和三键导航模式的逐帧表现未在本轮验证。专用 AVD 首次把仍获焦的搜索框移入分屏时曾唤起 IME；手动收起后可拖动分隔线，复测了草稿和重新打开键盘。该系统焦点转换与布局动效测试分别记录。

## 首轮真机与模拟器验证（基线）

| 官方用例 | 实测证据 | 尚需补验 |
|---|---|---|
| `T-Config_Orientation`、`T-Config_Combinations` | 小米 18 Fold（Android 17，440 dpi）用 `cmd device_state` 切换 OPENED / HALF_OPENED / CLOSED，系统默认窗口分别报告内屏 1672×2364、内屏横向 2364×1672、外屏 1168×1712，Activity 和进程未换。Android 16 模拟器用等比例分辨率分别覆盖 1:1、4:3、外屏 9:16 / 10:16，横竖转换后进入分屏、拖动分隔线、旋转、恢复全屏，再进入/调整自由窗口。其中 `areBoundsLetterboxed=false`，且 Activity/进程不变。 | 模拟器尺寸覆盖不等于官方折叠 AVD 的铰链。HyperOS 软件 CLOSED 时外屏在运行应用的测试中熄灭，即使发送 WAKEUP 未点亮，外屏真机画面、亮屏跨面板输入法与真实机械折叠仍需手动验收。 |
| `T-Config_State` | 真机搜索编辑器在竖屏 → 横屏 → 竖屏中保持草稿、焦点及开启的 IME；通过闭合→半开→展开时保留草稿。100 行合成搜索结果滚动后，回到展开竖屏仍是第 005 行，同样的可见偏移。模拟器同一草稿跨尺寸与方向保留；Back 先关闭 IME，不离开搜索。AMLL 的合成歌词、当前进度和控件在宽、方及短窗口可见。 | 真机闭合导致 OEM 关屏时 IME 被系统隐藏，不把该场景算作外屏 IME 通过。同进程 Activity 重建已由上面的第 3 轮补验；仍未逐一验证所有登录页面和深分页的进程死亡恢复。 |
| `T-Multi-Window_Functionality`、`T-Multi-Window_Focus` | Android 16 模拟器与系统时钟进入真实分屏，拖动后测到 `608×304dp`、旋转后 `288×608dp`，两边仍可操作；约 `474×241dp` 的自由窗口可从首页进「我的 → 设置 → 账号」并滚到列表底部。实际播放 90 秒合成 WAV，时钟获焦且音乐应用仍可见时，MediaSession 保持 `PLAYING`，进度 `23,436 → 26,464ms`，退出分屏后页面为 `0:29`。 | HyperOS 的测试用系统设置页不能作为分屏搭档，真机未取得分屏实测；需使用非隐私且支持分屏的搭档另验。Googlebook/ChromeOS 的桌面窗口最小化、最大化与恢复未验；现有模拟器是 Android 自由窗口，不是完整桌面 Shell。 |
| `T-Multi-Window_Resources` | 自动化覆盖录音中切走即取消采样、归还播放、回到本窗口可手动重试，以及匹配结束时不得在后台重新抢占麦克风。 | 在真实分屏与另一录音应用之间交接麦克风。 |
| `T-Keyboard_Input`、`T-Mouse_Trackpad_Basic` | 模拟器直接注入键盘字符、Ctrl+A/Delete、Back，并实际点击软件键盘字符；鼠标点击导航、鼠标滚轮滚动账号列表。 | 实物键盘热插拔、触控板与文本双击选择的全页面覆盖。 |
| `T-Stylus_Basic`、`T-Stylus_Text_Input` | 文本输入走 Compose Foundation/Material 的原生编辑器，Android 14+ 的普通字段使用[系统手写支持](https://developer.android.com/develop/ui/compose/touch-input/stylus-input/stylus-input-in-text-fields)。密码/验证码沿用相应安全输入类型。 | 缺少兼容手写笔和 IME，实际手写编辑不视为通过。 |
| `T-Camera_Preview`、`T-Media_Projection` | 不适用：没有摄像预览或系统投屏录制；二维码是生成供另一设备扫码，不占用摄像头。 | — |

真机用第一版适配候选包验证折展和输入；短窗布局、模拟器窗口矩阵和分屏播放再用后续候选包复测。`.debug` 与正式应用并存，不覆盖正式应用。真机状态覆盖、模拟器分辨率/方向/输入法与自由窗口设置均已恢复；测试用内网映射与音频已移除。若真机调试版仍启用了测试用的 QQ 服务器，可在「账号与服务」关闭 QQ 音乐或恢复原地址，不影响正式版。测试截图使用合成歌词或无账号页面，不代表已提交的商店素材。

## 复测

```powershell
.\gradlew.bat :androidApp:assembleDebug :shared:jvmTest :shared:testAndroidHostTest :shared:compileKotlinWasmJs :desktopApp:compileKotlin
adb devices -l
adb -s <serial> install -r androidApp/build/outputs/apk/debug/androidApp-universal-debug.apk
adb -s <serial> shell am start -W -n com.leejlredstar.redefinencm.kmp.debug/com.leejlredstar.redefinencm.kmp.MainActivity
```

1. 用调试账号或合成数据打开搜索，输入未提交文本并显示软键盘。旋转、折叠/展开、进入分屏并拖动分隔线，比较草稿、光标/选择和焦点；先手动按 Back 关闭键盘再重复，键盘不应无故出现。对结果列表滚至中段后重复，比对可见条目与偏移。
2. 在正在播放、队列滚动后、歌词展开后重复上述变化。分屏中让时钟等不抢占音频焦点的应用获焦，用 `adb shell dumpsys media_session` 核对调试包的播放器状态与播放位置；再用录音应用复测麦克风交接。检查 `dumpsys activity activities` 和 `dumpsys window` 的 Activity、窗口矩形及 letterbox 状态，系统任务栏不算应用黑边。
3. 让页面保持在同一路由，录制一次改变布局的折展。检查新位置只有一组控件可触达，背景与编辑器不跟着闪动；再比较同布局半折、快速反折、分屏拖动和键盘开关。在专用测试设备上把开发者选项「动画程序时长缩放」设为「关闭动画」，重复折展后恢复原值。系统窗口自身的过渡不算应用动效。
4. 真机用实际铰链和 OEM 允许外屏继续使用应用的设置验证亮屏切换。再用 Android Studio 的 Foldable（1:1/4:3 inner display）官方 AVD 跑同样矩阵，连接外接键盘、鼠标/触控板和手写笔。按 [Google 的截图规格](https://developer.android.com/google/play/requirements/screenshots-android-cli) 准备 1:1 展开、4:3 展开、10:16 折叠三张真实屏幕素材；另保留标准的两张手机截图。
