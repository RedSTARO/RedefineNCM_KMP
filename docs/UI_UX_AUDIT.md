# UI / UX 审计（使用者视角）

- 基线：`main` @ `a3cf5a7`（2026-09-19）。
- 方法：
  - 通读 `shared/src/commonMain` 全部 UI 代码与各平台外壳（`desktopApp`、`androidApp` 的 `MainActivity`、`wasmJsMain` 入口、各平台 `BackHandler` actual）。
  - 桌面端以 `./gradlew :desktopApp:run` 实际运行（Bash 启动，使用隔离的偏好副本，已登录；系统深色主题），在 1280×820（默认）、1280×1000、412×900（手机宽度的紧凑布局）三种窗口下截图核对。为避免向真实账号上报播放记录，全程未开始播放，播放页、歌词页均在暂停状态下观察。
  - 标【已验证】的条目在运行中看到；标【待运行验证】的只由源码推出；其余为源码中可直接确定的行为。
- 未覆盖：Android / iOS 真机或模拟器运行（iOS、Android 条目按源码判断）；听歌识曲的录音过程（需要麦克风录音，未执行）。
- 影响类型（描述性分类，不代表优先级）：
  - **阻断**：某项常见任务在该平台上无法完成。
  - **摩擦**：能完成，但多出步骤、需要猜、或结果与操作预期不一致。
  - **一致性**：同一概念在不同位置的表现、命名、图标、颜色不同。
  - **打磨**：视觉、文案、动效层面的问题。
- 平台列：全平台 / Android / iOS / 桌面 / Web；「移动」= Android + iOS + 窄屏 Web。
- 状态列（2026-09-19，对应提交 `7b4b2f3`）：
  - **已修复** / **部分修复**：对应改动的说明；标【已验证】的在桌面端运行中看过，其余只经过编译和测试。
  - **待决定**：需要产品层面的取舍（导航结构、默认值、视觉策略、新功能等），本轮未改。
  - 第二部分的「未处理」/「部分」只说明本轮是否顺带覆盖，这些本来就不是缺陷。

第一部分列现有界面中的问题；第二部分单列与成熟客户端相比缺失的功能。
